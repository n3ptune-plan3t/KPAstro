# Celebrity retrospective benchmark

This manually curated dataset tests one narrow question: does the engine include a documented marriage month among its KP month candidates?

## Method

- Calculate each natal chart from the listed local birth time, historical UTC offset and coordinates.
- Evaluate the canonical `marriage` event rule.
- Find qualifying Dasa–Bhukti–Anthara periods.
- A candidate month is generated by the Sun crossing the corresponding Reader 5 sensitive sign/star/sub zone.
- Moon, Jupiter and running period-lord crossings of the same zone/month are recorded as corroboration.
- Report event-month hit, number of candidate months, candidate density over the birth-to-event horizon, and nearest candidate month.
- No pass/fail threshold is applied. This is a diagnostic, not proof.

## Provenance and inclusion

Each listed Astro-Databank record was individually inspected. The dataset carries factual birth/event fields, Rodden rating, short source note and direct URL. AA indicates a birth-certificate/birth-record source. Do not automatically scrape or bulk-download Astro-Databank. Exclude A, B, C, DD, X and unknown times from the primary month-timing cohort; lower-quality birth times belong in a separate sensitivity analysis.

The benchmark uses one marriage per person. Historical local offsets are recorded explicitly to keep the input reproducible.

## Interpretation safeguards

1. Freeze the method before interpreting results. Do not tune the engine on this sample.
2. Candidate density is essential: a predictor flagging many months can hit event months by chance.
3. This dataset is small, non-random and restricted to marriage. It cannot establish general predictive validity.
4. Do not rectify birth times against the same event used to score the prediction.
5. A failed case remains in the report; do not silently remove it.
6. This is retrospective research into an astrological tradition, not a scientifically validated forecast.
