# Celebrity retrospective benchmark

This is a DEVELOPMENT dataset, not a sealed holdout. Do not use it for final performance claims. It is a manually curated exploratory sample that tests one narrow question: does the engine include a documented marriage month among its KP month candidates?

## Method

- Calculate each natal chart from the listed local birth time, historical UTC offset and coordinates.
- Evaluate the canonical `marriage` event rule.
- Find qualifying Dasa–Bhukti–Anthara periods.
- A candidate month is generated by the Moon crossing the corresponding Reader 5 sensitive sign/star/sub zone during a qualifying Dasa–Bhukti–Anthara.
- Sun is recorded as the broader within-a-year check; Jupiter is optional broad corroboration; running DBA-lord crossings are recorded as separate evidence.
- Report event-month hit, number of candidate months, candidate density over the birth-to-event horizon, and nearest candidate month.
- No pass/fail threshold is applied. This is a diagnostic, not proof.

## Provenance and inclusion

Each listed Astro-Databank record was individually inspected. The dataset carries factual birth/event fields, Rodden rating, short source note and direct URL. AA indicates a birth-certificate/birth-record source. Do not automatically scrape or bulk-download Astro-Databank. Exclude A, B, C, DD, X and unknown times from the primary month-timing cohort; lower-quality birth times belong in a separate sensitivity analysis.

The benchmark uses one marriage per person. Historical local offsets are recorded explicitly to keep the input reproducible.

## Interpretation safeguards

1. Freeze the method before interpreting results. Do not tune the engine on this sample.
2. Candidate density is essential: a predictor flagging many months can hit event months by chance.
3. This dataset is small, non-random and restricted to marriage. It cannot establish general predictive validity.
4. Do not rectify birth times against the same event used to score the prediction.
5. A failed case remains in the report; do not silently remove it.
6. This is retrospective research into an astrological tradition, not a scientifically validated forecast.

## Correct evaluation order

1. Audit all 56 event rules against their original Reader passages. Mark each as verified, partial or unverified, and document conditions that the current engine does not implement.
2. Correct the timing implementation from the source sequence: natal promise, DBA significators, period-lord transits through joint sensitive zones, Sun as the within-a-year check, Moon as the within-a-month check. Keep Jupiter explicitly optional unless a primary KP source establishes its role for that event.
3. Add unit tests and Reader worked-example tests for each audited rule. Do not use celebrity outcomes to change source doctrine.
4. Freeze the rules and timing algorithm. Use the existing celebrity cases only as an exploratory/development diagnostic.
5. Build a separate holdout dataset from different people and event records. Keep it sealed until the method and scoring rules are frozen. Do not repeatedly tune against its results.
6. Report hit rate together with candidate-month coverage/density, event-type breakdowns, sample size, birth-time source quality and uncertainty. Compare with a simple baseline. Do not describe retrospective performance as prospective predictive accuracy.

This order follows standard evaluation practice: train/development and validation data can inform changes; the final test set must remain untouched. For time-dependent forecasting, preserve chronological boundaries and avoid information leakage.


## Expanded development cases (not independent people)

A second file, `celebrity-events.json`, exercises non-marriage event keys: job, property purchase, childbirth, divorce and second marriage. It currently uses dated public event records for Amy Rodden, Anne Rodden and Jon Rodden, all with AA birth-record ratings. Multiple events from the same person are correlated and must not be counted as independent chart samples. This is code-path coverage and exploratory diagnosis only; it is not a substitute for a larger, multi-person development cohort or the sealed holdout.
